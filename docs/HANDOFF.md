# Handoff: luce-js and the luce-browser port

Start here when picking this work up on a new machine. The state below is as of 2026-09-26.
luce-js is the JavaScript engine of the future Luce web browser. The browser itself is a port of
Ladybird's LibWeb in the `luce-browser-*` packages.

## 1. What to check out

Put everything side by side in one directory (packages refer to each other by `../<name>`
paths):

```sh
mkdir luce_dev && cd luce_dev
for r in luce-js luce-regex luce-std luce-compress luce-base \
         luce-browser-foundation luce-browser-css luce-browser-html \
         luce-browser-render luce-browser-engine luce-browser-tools; do
    git clone https://github.com/dymokomi/$r
done
```

The compiler is Luce 0.8.12 (luce-base `ca67a3e`, pinned in every repo's `bootstrap/BASE`):

```sh
git -C luce-base checkout ca67a3e && (cd luce-base && ./build.sh)
export PATH=$PWD/luce-base/build:$PATH
```

To match the pins exactly, check out the commits in each repo's `bootstrap/PACKAGES`, which is
what CI does. For work, the heads of main are fine.

Reference sources ("donors") are only for local comparison and never go into these repositories:
- QuickJS, for luce-js: https://github.com/bellard/quickjs at `04be246` (VERSION 2026-06-04);
  `make qjs` gives the C engine that `tests/bench.py` compares against.
- test262: `tests/test262.py` fetches its own checkout at `5c8206929d` and applies QuickJS's patch.
- Ladybird, Skia m144 and tiny-skia, for the browser: see `luce-browser-tools/DONORS.md`.

## 3. Rules the owner set

- Repositories hold only Luce code, test data and the harness CI runs. C/C++ donor code and
  comparison drivers stay local (they live in luce-browser-tools, not in the packages).
- Tests pass locally before any commit. Commit only on green: never chain `git commit` after a
  piped command. CI runs on every push.
- Code bar: faithful to the donor, fragments of at most about 600 lines with header boxes,
  `# mark:` sections and `##` docs on pub declarations. `luce-base check -W` must print nothing
  (it exits 0 on warnings in 0.8.12; `test.sh` treats any output as failure). `luce-base fmt
  --check` is enforced in every `test.sh`; generated files are excluded.
- No backward compatibility; there are no users yet.
- Spell it Color/color.

## 4. How the work is done

**luce-js.** Conventions are in `docs/PORTING.md`, speed in `docs/PERFORMANCE.md`. The gate:
`./test.sh` and `python3 tests/test262.py`, which must print `Result: 58/83558 errors` with
0 crashes: exactly C QuickJS's failures. Publish with `luc publish -m "..."` after bumping
`package.prisma`, then verify with a fresh `luc add` (set `LUC_HOME` to a temporary directory).

**Browser regions.** Each package was generated as typed stubs (`stub_rNN_*.lucb` fragments)
by `luce-browser-tools/skeleton`. Porting then goes in rounds:
1. One agent per region, each in its own git worktree on branch `port/<region>`, given
   `luce-browser-tools/briefs/region-brief-template.md` with the region's line from
   `docs/regions.tsv` filled in. The agent ports faithfully, pins tests to the donor with local
   oracles, writes `docs/regions/<region>.md`, and commits on its branch only.
2. Then an integrator agent merges the branches in dependency order. It reconciles the stub
   signatures regions changed in each other's code, flips the test gates
   (`*_is_ported = false` flags) and fixes what the newly running tests expose.
3. Then verify `./test.sh` with the pinned compiler, push, and watch CI on macOS and Linux.
   Remove merged worktrees afterwards.

Pitfalls learned:
- Conservative-GC tests are codegen-sensitive: keep cell addresses in `noinline` helpers.
- Linux-only failures come from x86-64 unreachable-code warnings, macOS-only externs in test
  builds, and libm last-bit differences in bit-exact float tests. Write platform branches as
  if/else.
- Big test modules need `noinline` test bodies (ranges_facts_cubic) until the next Luce
  release.

## 5. Open work, in order

1. **luce-browser-render Linux CI.** Test "sk path: arc_ff" (gfx/tests_sk_path_cases.lucb):
   142 of 323 SVG coordinates are 1 to 3 f32 ulp lower on x86-64 than the macOS/Skia values
   (arm64 fuses multiply-adds, x86-64 v1 does not). The owner is deciding between:
   - a small ulp tolerance off macOS, as `gfx/tests_color_1.lucb`'s `libm_ulps` does for libm;
   - fusing explicitly with `mul_add` once the next Luce release has it, so every platform
     matches Skia's arm64 bits.
2. **luce-std 0.1.2** (`6550a6f`, warning-free) is published. Moving the pins to it is on hold
   until the owner decides how. After that, web_fonts' own directory walk (nftw/_findfirst64 in
   `font_database`) can use luce-std's `files`.
3. **Next Luce release.** luce-base has fixes for most of `docs/COMPILER-REQUESTS.md` on the
   local branch `compiler-requests` (63b2798, d9c6dc7, eca8ab7), gated green here on arm64
   against luce-js and every browser package. LUCED-2D also wants its `crash-unwind` branch in
   0.8.13. Pushing and releasing are the owner's call. When a release lands:
   - pin it in every `bootstrap/BASE`;
   - rerun all gates, plus x86-64 through CI or the LINUX session;
   - drop the workarounds marked `# workaround: compiler-issues/...`: noinline test bodies,
     float bits through a pointer, `sizeof(T)`, generic function values, the asm x19 test,
     `const (T[N])*`;
   - update `COMPILER-REQUESTS.md`.
4. **The engine (luce-browser-engine), phase 1.** Static rendering with scripting disabled:
   HTML parser → DOM → CSS → layout → paintables → display list → CPU raster. The exit bar is
   in DESIGN §1/§3: Layout 854 runnable tests (target ≥ 95%), Ref 627, Crash 47. There are 44
   regions in `docs/regions.tsv` (r13–r56), plus the headless `web_test` runner and the Luce
   code generators DESIGN lists. The engine repo still needs `bootstrap/` and CI like the
   others. Engine follow-ups already known from earlier regions:
   - Delete the 10 CSS/Serialize stubs and call `css_syntax`'s versions.
   - Set `css_syntax.invalid_rule_location_reporter`.
   - Add `[T: TokenStreamToken[T]]` constraints on generic parser functions.
   - Drop the `css_is_*custom_property_name_string` stubs (moved to css_data).
   - HTMLParser uses `html_tokenizer_set_parser` (see html's `docs/regions/r20.md`).
   - Forward `ScrollbarColorData`/`scrollbar_color()` to display_list.
   - Root `FontDatabase::the()`.
   - Clone css_data's shared static Vectors before changing them.
5. **Render fidelity left over** (render `INTEGRATION.md`):
   - glyphs are filled from unhinted outlines where Skia uses FreeType's hinted masks (no
     TrueType hinting yet);
   - box shadows use a box blur rather than Skia's mask blur (1 level);
   - transforms are 2D only;
   - WOFF2 needs a Brotli decoder;
   - no complex-script shapers;
   - raster is 5–30× slower than tiny-skia.
6. **luce-js speed.** Microbench geometric mean 2.86× C QuickJS on 0.8.12. What remains is
   compiler work (items 2, 3, 6, 7 of `COMPILER-REQUESTS.md`), then the port-side gaps listed
   in `PERFORMANCE.md`.

## 6. People and sessions

Other Claude sessions on the owner's machines take messages by name:
- **LUCE_AND_LUCE_BASE** fixes luce-base compiler bugs. Send it new items and the numbers from
  `docs/COMPILER-REQUESTS.md`, which stays the written list.
- **LUCED-2D** is the main development session: luce-std, releases, luced-2d.
- **LINUX** (Ubuntu x86-64) and **WINDOWS** run tests on their platforms. Send them exact steps
  and pushed commits, and ask them not to commit or publish.

The owner decides on pushes to luce-base, Luce releases and anything outside luce-js and the
luce-browser repositories.
